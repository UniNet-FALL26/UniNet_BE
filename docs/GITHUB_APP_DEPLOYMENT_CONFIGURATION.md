Keep the separate existing OAuth app settings `GitHub__ClientId`, `ClientSecret`, `CallbackUrl`, return targets and legacy webhook settings. Existing OAuth callback is `/api/github/oauth/callback`. Configure GitHubSync separately when the worker should run. GitHub API endpoints are not configured from untrusted input.

When App is enabled or `ValidateDeployment` is enabled, startup requires those App credentials, an HTTPS callback and return target, existing OAuth credentials/HTTPS callback, a fully qualified existing `GitHub__KeyRingPath`, and `GitHub__KeyRingCertificatePath`. It validates an RSA private key and a usable RSA certificate without printing their contents. This does not establish GitHub-side correctness, webhook configuration, shared storage, certificate trust or actual worker health.

## Data Protection

The existing application discriminator `UniNet.GitHubIntegration` and purpose `UniNet.GitHubOAuth.Token.v1` remain unchanged. Use a persistent, access-controlled shared filesystem mounted identically on every instance. Mount a PFX with private key through the deployment secret system and set `GitHub__KeyRingCertificatePath`; use `GitHub__KeyRingCertificatePassword` when needed. New key-ring files are encrypted with the certificate. Back up the shared ring and certificate private key; preserve old keys and previously used certificates for as long as their ciphertext exists. Configuring a certificate does not retroactively encrypt old XML files. Coordinate any storage, discriminator or encryption change with existing ciphertext: moving to an empty ring makes existing OAuth credentials and durable webhook deliveries unreadable.

For certificate rollover, set the new PFX as `GitHub__KeyRingCertificatePath` and mount every older PFX still protecting keys under `GitHub__KeyRingPreviousCertificates__0__Path`, `__1__Path`, etc.; each has an optional `__Password`. New keys use the current certificate and old keys can be decrypted using the retained certificates. A local test verifies old ciphertext after rotation, creation of a new key and restart. Rollout across hosts, storage recovery and private-key access policies still require deployment-specific validation. Do not remove an old certificate or key until its ciphertext retention has been verified. Never ship private keys, PFX files, passwords or key-ring backups in source control.

## Operational readiness

`/health` remains the original liveness endpoint. `/health/github/readiness` requires App and GitHub Sync enabled, then checks configuration, database connectivity, pending EF migrations and a local protect/unprotect round trip; it returns a generic health result. It does not check cross-instance decryption, persistence after restart, worker/consumer liveness, scheduling progress or GitHub API access. Restrict probe access at the deployment boundary. Establish explicit monitoring for worker and reconciliation progress before production.

`/health/github/instance` is a separate, per-process signal: it records successful worker poll, webhook consumer and reconciliation cycles and uses a 15-minute startup/staleness threshold. Empty queues count as successful cycles. Disabled App/sync reports Degraded. A long-running cycle can exceed this threshold; this endpoint is not a shared-queue health signal and must not be used alone to declare a multi-instance deployment unhealthy. It does not yet measure eligible backlog, expired leases or shared progress.

`/health/github/queue` inspects durable App jobs, webhook deliveries, expired leases, reconciliation deadlines and shared worker cycle timestamps. It reports Degraded after `GitHubApp__QueueHealth__WarningMinutes` (default 15) and Unhealthy after `GitHubApp__QueueHealth__CriticalMinutes` (default 60); critical must exceed warning. Retry and reconciliation deadlines in the future are not overdue. App disabled returns Degraded. Heartbeats expire after two minutes; absent fresh progress is Unhealthy. The probe uses status/deadline indexes and bounded `EXISTS` checks with a five-second command timeout; database errors return Unhealthy. Long-running consumer/reconciliation cycles and query plans require further validation.
