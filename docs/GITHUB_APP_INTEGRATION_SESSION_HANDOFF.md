## A. Project context

UniNet Backend uses ASP.NET Core, EF Core and PostgreSQL. Domain holds entities and enums, Application holds contracts and services, Infrastructure holds EF mappings and migrations, and API hosts controllers, provider clients and the existing background worker. GitHub App onboarding is intended to automate repository access and sync while retaining existing GitHub OAuth account linking and identity mapping. OAuth identifies and authorizes the linked GitHub user; an App installation grants the application access to selected repositories. App user credentials, installation tokens, and OAuth credentials have different purposes and must not be conflated.

## B. Decisions already finalized

- Use GitHub App installation with a shared App webhook; Step 4 will implement its lifecycle routing. Retain existing OAuth account linking and OAuth repository flows.
- Model OAuth-backed and App-backed repositories explicitly. Never fall back from App to OAuth, or use an App user token as the worker token.
- Only the Project Creator or authorized Git Manager may link a repository; verify the GitHub user's admin and read permissions live. An installation's access alone does not prove the user's authority.
- Scope installation tokens to the correct installation and repository. Never expose tokens or private keys.
- Preserve Git Activity and its project visibility when access is lost; protect shared repositories and cross-project isolation.
- Reuse the existing sync worker, job lifecycle, checkpoints and activity pipeline. Do not hardcode localhost, ngrok or production URLs.
