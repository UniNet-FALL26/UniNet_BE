# Admin skill catalog

Replaces Dashboard mock skills with persisted Skills and distinct Student UserSkills counts. Reuses nullable Category enum (Frontend=0, Backend=1, Design=2, ToolsAndOther=3), IsActive and existing references. No migration. No global proficiency level: Level belongs to UserSkill rather than Skill.

Design update: API items also return existing `Skills.IconUrl`. `sort=name` (default) or `sort=popular` sorts before server pagination. Dashboard defaults to 12 cards/page, supports 12/24/48, numbered navigation and popularity/name sorting. Compact horizontal cards render the stored icon via a validated HTTP(S) URL, with a blue Award fallback only when absent/invalid or loading fails. No invented logo mapping, categories or usage states. Existing save operations preserve IconUrl.

Icon editor: create/edit form accepts JPG/PNG/WebP <=5 MB with local preview, optional background removal and restore-original action. POST `/api/admin/skills/icons/remove-background` (Admin, multipart file) returns PNG without uploading or mutating DB; uses existing local U2NET model, not portrait Gemini prompts. Processing is serialized with 429 when busy and a clear failure message if the image cannot be separated. POST `/api/admin/skills/icons` validates/decodes image, normalizes orientation/size <=512px and uploads PNG via existing signed Cloudinary storage. Save payload adds optional `iconUrl` (validated HTTPS res.cloudinary.com image delivery); omission preserves existing icon. Upload happens only on Save and is cached for a retry after validation errors. No schema change, no secret on frontend and no arbitrary URL fetching. Cancelling after a successful upload but failed skill save may leave an unreferenced Cloudinary asset; assets are not automatically deleted to avoid removing shared references.

Dark background fix: normalized icons with >=95% uniform opaque dark border use edge-connected color removal first, preserving enclosed dark details. Blank dark images return actionable 422 rather than a meaningless model mask. Other images retain U2NET; missing model/native runtime errors map to 503, cancellation is preserved. Tests reproduced the blank-black defect and passed black-background transparency/enclosed detail checks plus original processing/upload tests (4 passed). Exact production 500 from the user's screenshot could not be confirmed without Render logs/original file. Deploy BE changes to apply. UI overlays a blue scanning line while processing, stops on success/failure, respects reduced-motion and retains original preview after errors; Chrome verified actual CSS movement and error/retry behavior, lint/build passed.

All-color update supersedes the dark-only shortcut: edge-connected removal now handles any opaque uniform border color; white/red/blue/green/yellow/purple and black tested with exact foreground/enclosed-detail preservation. Patterned/gradient/nonuniform backgrounds continue through U2NET. Icon processing is independent of portrait occlusion rejection, and the UI does not restrict by background color. No guarantee of perfect separation for every image, especially foreground matching the background color.

Consistent visual size: `SkillIconImages.FitToCanvas` trims transparent margins or uniform-color border padding, fits the visible bounds into 448px on a centered 512x512 PNG and preserves aspect ratio. Uniform opaque backgrounds keep their color; transparent inputs keep transparency. Nonuniform opaque borders are retained rather than guessed. Admin POST `/api/admin/skills/icons/preview` returns this normalized PNG without Cloudinary writes. Dashboard prepares each selected image using that endpoint; removal results and Cloudinary upload use the same normalization. Inputs/save are disabled while preparing, requests are aborted on close, original-before-removal remains available. Historical stored images are not bulk rewritten; reselect/reupload to normalize them. Extremely wide/tall artwork still keeps its natural aspect ratio rather than stretching.

Validation for size update: 15 focused backend tests passed, including padding trim, opaque/transparent canvas, wide-logo aspect ratio and HTTP preview authorization/dimensions; Dashboard targeted lint/build and Chrome management fixture suite passed. No migration, real Cloudinary writes, production deploy or commit.

New Admin-only endpoints: GET `/api/admin/skills?search=&category=&isActive=&page=1&pageSize=20`; POST same route; PUT `/{id}`. Writes accept `{name,category,isActive}`. GET returns `{items,page,pageSize,total}` with each `{id,name,category,isActive,studentCount}`. Names trimmed, required, <=100; categories null or 0..3; stable name/ID sort, size<=100. Duplicate names including inactive return 409, missing ID404, invalid filters400, unauthorized staff403. All operations recheck active Admin account. PostgreSQL advisory transaction lock serializes catalog writes to prevent duplicate-name races through these endpoints. Existing `/api/profile/skills` contract unchanged; no hard deletion of used skills.
